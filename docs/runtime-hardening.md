# Runtime hardening status (Goal A)

Harness: `tests/harden-runtime-test.sh` (run with `sudo`). 10/10 pass. Every
scenario leaves no `inet exitlag` table and no helper process, including on
failure. Traffic is generated by a native Linux probe, so no game is required.

## Automated and passing

| Scenario | What it proves |
|---|---|
| repeated start/stop cycles (5x) | table installed and removed cleanly every cycle |
| stale nftables detection | pre-flight refuses to start on a leftover table (exit 3) |
| fail-open, no helper | rules installed + helper dead -> traffic still flows (`queue ... bypass`) |
| helper SIGKILL mid-run | traffic survives an abrupt helper death |
| owned runner SIGKILL recovery | an orphaned helper and its table are recovered on the next start |
| runner SIGTERM | the EXIT trap tears down before exiting: no table, no helper |
| runner SIGINT | same, via the Ctrl-C path |
| shim reconnect | shim times out a silent endpoint and reconnects to a fresh helper |
| protocol version mismatch | helper logs `protocol version mismatch` and fails open |
| unreachable destination | helper survives a dead destination and still routes afterwards |

The unreachable-destination case uses TEST-NET-3 (203.0.113.1, RFC 5737), so it
simulates network failure without touching any route or interface.

These three signal cases are deliberately separate. SIGKILL cannot run a trap,
so it tests *recovery on the next start*; TERM and INT can, so they test that
cleanup happens immediately and nothing is left for recovery to find.

## Verified live, not automated

- **ExitLag restart** — restarted onto the production launcher; the shim
  reconnected to a helper that was started afterwards (`shim connected`,
  `hello: shim protocol=2`), and after the IPC peer check was added, as
  `shim peer uid=1000 accepted`.
- **Wine restart** — `wineserver -k` between runs; the helper sees the shim
  disconnect, fails open, and accepts the new connection when the prefix comes
  back. No stale IPC state survives, because the helper holds no shim state
  across a disconnect beyond the socket itself.
- **Game restart** — WoW was restarted twice with the helper live; TCP redirect
  re-armed each time.
- **Battle.net restart** — launcher traffic correctly classified as fail-open
  ACCEPT (not proxied) across restarts.

These need a real client/game and are impractical inside a root harness (ExitLag
must not run as root).

## Runtime ownership

`backend/runtime-guard.sh` (sourced by the active runners, not a command) gives
the backend a single owner:

- an `flock` on `/run/exitlag-linux/backend.lock` — a second runner refuses to
  start rather than fighting over the queue
- a pidfile recording the helper PID **and** its resolved binary path, so a
  recycled PID belonging to an unrelated process is left alone
- on startup, an orphaned helper from a SIGKILLed runner is terminated and its
  `inet exitlag` table removed
- a table with no verifiable project ownership is **not** deleted automatically;
  the runner refuses instead
- the lock descriptor is closed in spawned children, so a runner killed with
  SIGKILL cannot leave its helper or timer holding the lock forever
- `runtime_guard_wait` returns as soon as the helper dies, so the EXIT trap
  removes the nftables surface immediately instead of leaving it fail-open
  until a long timer expires

## Heartbeat

The helper sends `EXL_MSG_PING` every 2s and the shim answers `EXL_MSG_PONG`;
the shim also sets 5s send/receive timeouts on its socket.

This closes a real hang: Wine can leave a loopback connection *established*
after the helper is gone, which would otherwise pin the shim's thread forever
waiting on a peer that will never answer. The timeout converts that state into
the ordinary fail-open reconnect loop.

## Logging

`EXITLAG_NFAPI_TRACE=1` enables the full research trace. Without it the shim
logs only lifecycle and compatibility events (`compat.install`, `policy.mode`,
`nf_init`, `nf_free`, the `ipc.*` lifecycle) plus any explicitly unsupported
call — an unsupported capability is always logged, because it is an operational
warning rather than trace noise. The research launchers set the variable; the
production launcher clears it.

## Update safety

`tools/run-exitlag-production.sh` now runs `tools/check-exitlag-version.sh`
before launching and refuses to start a private-ABI shim against an ExitLag
build the runtime has not been verified against. The research launchers do not,
so deliberate work on a new build is still possible.

## Not yet covered

- Physical link down/up (as opposed to an unreachable destination).
- Long-duration soak. Longest continuous run so far is ~25 minutes.

## Production path no longer depends on debug hooks

This was a real defect, not tidying. `policy_succeeds` returned **false** for
every export unless `EXITLAG_NFAPI_SUCCEED` named it, so a correct build
behaved as unimplemented whenever the launcher omitted a function. That is
exactly what made the post-guard UDP regression look like a failure: the session
lacked the UDP entries, `nf_udpPostSend` returned -1, and the helper correctly
failed open.

Now:

- `k_supported_exports` in the shim lists the twelve exports the Linux backend
  implements; those succeed with no configuration. Anything outside the table
  still fails explicitly, so an unimplemented capability degrades rather than
  pretending to work.
- `EXITLAG_NFAPI_EXTVER` defaults to 8 (`EXITLAG_SUPPORTED_EXTENSIONS_VERSION`).
- Both variables remain **research overrides**, consulted only when set.
- `nf_init` logs `policy.mode source=built-in-table|EXITLAG_NFAPI_SUCCEED-override`
  so no capture is ever ambiguous about which surface it exercised.
- `tools/run-exitlag-production.sh` runs with none of the research
  instrumentation. `tools/run-exitlag-gameprefix.sh` is unchanged for research.

Verified live on the real client:

```text
compat.install  state=done guards=11/11
policy.mode     source=built-in-table supported=12
nf_init         driverName="nfextlag" policy=succeed return=0
nf_getExtensionsVersion  policy=succeed return=8
```

## Known operational gotchas

- The runner scripts' cleanup trap **cannot fire while bash is blocked in its
  foreground `sleep`**. To stop a run early, kill the `sleep` child; signalling
  the script does nothing until the sleep returns.
- `pkill -f run-udp-steer.sh` matches the killing shell's own command line.
  Kill by PID.
- Shim builds are **not byte-reproducible** (PE timestamp), so compare
  behaviour, not hashes, across rebuilds.

## Log bounds

Both sides cap their logs at 8 MB and keep one previous generation, so a long
session cannot fill the disk. During development a single ExitLag session with
the research trace enabled produced an 11 MB log, and several runs left tens of
megabytes behind.

- Helper: rotates `<log>` to `<log>.1`, then records why in the new file.
  Checked every 256 lines rather than per line. `EXITLAG_LOG_MAX_BYTES`
  overrides the threshold, which is how rotation is tested without generating
  8 MB.
- Shim: same bound and single previous generation, checked every 512 writes.

Verified: with an 8000-byte threshold, 400 log lines produced `r.log` (9979
bytes) plus `r.log.1` (14141 bytes) and the rotation notice in the new file.

What normal-mode logs contain: startup and shutdown, shim connect/disconnect and
handshake, identity translation decisions, routing events (DNAT armed, UDP
reinjection), refusals, warnings and errors, and cleanup. The full per-call
argument trace requires `EXITLAG_NFAPI_TRACE=1`.

Credentials are never logged. The shim records call arguments and packet
headers, not ExitLag account details; the helper logs addresses, ports, PIDs and
executable paths. Payload bytes appear only as a truncated hex head of at most
64 bytes, and only with the research trace enabled.
